# ACCL Collective Operations - C Implementation

This directory contains the C implementation for processing ACCL (Alveo Collective Communication Library) packet traces generated by the `generate_packet_trace.py` script in the PacketTraceGenerator directory.

## Directory Contents

### Core Implementation Files
- **`accl_packet_processor.h`** - Header file with structures, enums, and function prototypes
- **`accl_packet_processor.c`** - Main implementation (~600 lines) with all collective operation handlers
- **`demo_packet_processor.c`** - Demo program showing how to use the processor

### Build Files
- **`Makefile`** - Build system for Linux/Unix/WSL
- **`build.bat`** - Windows batch build script
- **`build.ps1`** - Windows PowerShell build script
- **`run_demo.bat`** - Complete demo automation (generates traces + builds + runs)

### Documentation
- **`README_C_PROCESSOR.md`** - Comprehensive technical documentation

## Quick Start

### On Windows

**Option 1: Using Batch Script (Simplest)**
```cmd
build.bat
```

Then run:
```cmd
demo_packet_processor.exe 3 ..\PacketTraceGenerator\output_single_node\accl_packet_trace_node3.bin
```

**Option 2: Full Demo (Automatic)**

```cmd

demo.exe 3 ..\PacketTraceGenerator\output_single_node\accl_packet_trace_node3.bin
```

### On Linux/Unix/WSL

```bash
make
./demo_packet_processor 3 ../PacketTraceGenerator/output_single_node/accl_packet_trace_node3.bin
```

## What This Code Does

- **Reads packet traces** in binary or hex format
- **Stream processing mode**: Processes packets one-at-a-time like real network (no buffering)
- **State tracking**: Monitors operation progress, completion, and phases (NEW)
- **Processes 11 ACCL operations** with accurate collective semantics:
  - Send/Receive (with message completion tracking)
  - Broadcast (tree-based distribution)
  - Scatter (chunk distribution)
  - Gather (ring-based collection)
  - Reduce (ring-based reduction)
  - Allgather (ring circulation)
  - Allreduce (reduce-scatter + allgather phases)
  - Reduce_Scatter (combined reduction and scattering)
  - Barrier (synchronization with entry/exit tracking)
  - Alltoall (all-to-all personalized exchange)
  - Combined operations

- **Handles protocols**:
  - Eager protocol (≤32KB messages)
  - Rendezvous protocol (>32KB with 3-phase handshake)

- **Tracks comprehensive statistics**:
  - Packet counts by type and operation
  - Data transfer volumes
  - **Directional byte counters** (bytes sent vs received) (NEW)
  - Protocol usage
  - **Per-operation progress and completion** (NEW)
  - **Session-based tracking** for concurrent operations (NEW)

- **Memory efficient**: O(1) memory usage - only one packet in memory at a time

## Design Principles

- **Binary Compatibility**: Exact 64-byte header matching ACCL hardware
- **Network Byte Order**: Big-endian format with proper conversion
- **Protocol Fidelity**: Faithful implementation of ACCL protocols
- **Cross-Platform**: Works on Windows, Linux, and macOS
- **Educational**: Clear code structure for learning ACCL internals
- **Stateful Simulation**: Tracks operation progress like real hardware (NEW)
- **Semantic Accuracy**: Handlers implement actual collective communication patterns (NEW)
