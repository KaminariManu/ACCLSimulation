# ACCL Packet Processor - C Implementation

## Overview

This C implementation provides a packet processor that simulates ACCL (Accelerated Collective Communication Library) operations based on packet traces generated by `generate_packet_trace.py`. It resembles the functionality of `ccl_offload_control.c` (found in the `ACCL code` directory) but processes pre-generated packet traces instead of live network traffic.

**Key Feature**: Uses **stream processing mode** - packets are processed one-at-a-time as they arrive (like real network traffic), with no buffering. This provides realistic network simulation behavior with O(1) memory usage.

## Files

- **`accl_packet_processor.h`** - Header file with data structures and function prototypes
- **`accl_packet_processor.c`** - Implementation of packet loading and processing
- **`demo_packet_processor.c`** - Demonstration program showing usage
- **`Makefile`** - Build system for compiling the code

## Features

### SoC Memory Simulation

The processor includes a **comprehensive SoC (System-on-Chip) memory simulation** that accurately models on-chip memory used for packet buffering and collective operation data storage:

#### Memory System
- **256 MB simulated on-chip memory** with realistic address space
- **Dynamic buffer allocation** with automatic memory management
- **Up to 128 concurrent buffers** for operations in flight
- **Memory tracking**: Monitors usage, peak allocation, and fragmentation
- **Address mapping**: Simulates physical addresses starting at 0x80000000

#### Memory Operations
- **Buffer allocation**: Automatic allocation when operations start
- **Data storage**: Stores incoming packet data in memory buffers
- **In-memory reduction**: Performs actual reduction operations on buffer data
  - SUM, MAX, MIN, PROD, LAND (Logical AND), LOR (Logical OR)
  - Operates on 32-bit values in network byte order
- **Memory deallocation**: Frees buffers when operations complete

#### Memory Usage by Operation
- **Reduce operations**: Allocates buffer on first packet arrival
  - Stores accumulated reduction result
  - Combines incoming data with buffer contents
  - Maintains result until operation completes
- **Other operations**: Can allocate buffers for data staging and assembly

#### Memory Statistics
The system tracks and reports:
- Total and used memory (with percentage)
- Peak memory usage during execution
- Number of active buffers with details:
  - Buffer ID and associated session
  - Buffer size and bytes used
  - Operation type (REDUCE, BROADCAST, etc.)

### Packet Loading
- Load packets from **binary files** (`.bin`) - Fast, compact format
- Load packets from **hex files** (`.txt`) - Human-readable, for debugging
- **Stream processing**: Packets processed one-at-a-time (no buffering)
- **Memory efficient**: Only one packet in memory at any time (O(1) memory)
- Automatic byte order conversion (network to host endianness)
- Header validation and protocol verification

### Packet Processing
- **Real-time simulation**: Each packet is processed immediately upon arrival
- **State tracking**: Monitors operation progress, message completion, and collective phases
- **Session management**: Tracks collective operations across multiple packets
- **Completion detection**: Identifies when multi-packet operations finish
- Process all ACCL packet types:
  - `DATA_EAGER` - Eager protocol for small messages
  - `RNDZV_ADDR` - Rendezvous address exchange
  - `RNDZV_DATA` - Rendezvous RDMA data transfer
  - `RNDZV_COMPLETE` - Rendezvous completion notification
  - `COLLECTIVE_DATA` - Collective operation data

### Operation Support
Implements **stateful handlers** for all ACCL operations that accurately simulate collective communication patterns:

- **Point-to-Point**: Send, Recv
  - Tracks pending messages with tag matching
  - Segment-by-segment progress tracking
  - Completion detection for multi-segment transfers
  - Separate send/receive byte counters

- **Collective One-to-Many**: Broadcast, Scatter
  - **Broadcast**: Root-to-all distribution (tree or flat topology)
    - Tracks cumulative bytes sent to all ranks
    - Detects broadcast completion
  - **Scatter**: Root distributes unique chunks to each rank
    - Tracks which ranks received their chunks
    - Monitors segmented delivery

- **Collective Many-to-One**: Gather, Reduce
  - **Gather**: Ring-based collection to root
    - Identifies root vs relay nodes
    - Tracks data collection progress
  - **Reduce**: Ring-based reduction with **in-memory data combining**
    - **Allocates SoC memory buffer** on first packet arrival
    - Stores accumulated reduction result in memory
    - **Performs actual reduction operations** (SUM, MAX, MIN, PROD, LAND, LOR)
    - Combines incoming data with buffer contents using specified function
    - Tracks partial results through ring
    - Extracts reduction function from packet tag field (bits 16-31)

- **Collective Many-to-Many**: Allgather, Allreduce, Reduce_Scatter, Alltoall
  - **Allgather**: Ring circulation where all ranks get all data
    - Tracks ring position and progress
  - **Allreduce**: Two-phase operation with **in-memory reduction**
    - **Phase 1 (REDUCE-SCATTER)**: Performs actual reduction operations in SoC memory
    - **Phase 2 (ALLGATHER)**: Gathers reduced chunks to all ranks
    - Allocates buffer on first packet, performs reduction during phase 1
    - Identifies current phase and applies appropriate operation
    - Tracks both scatter and gather stages
    - Supports all 6 reduction functions (SUM, MAX, MIN, PROD, LAND, LOR)
  - **Reduce_Scatter**: Combined reduction and scattering with **in-memory operations**
    - **Allocates SoC memory buffer** for chunk accumulation
    - Performs actual reduction on incoming chunks
    - Each rank maintains buffer for its designated reduced chunk
    - Combines incoming data with buffer contents using reduction function
    - Monitors chunk distribution and completion
  - **Alltoall**: All-to-all personalized exchange
    - Tracks send/receive matrix

- **Synchronization**: Barrier
  - Entry/exit phase tracking
  - Ranks participation counting
  - Synchronization point detection

## Baremetal Compatibility

The ACCL Packet Processor is designed to work in **baremetal environments** without external library dependencies. All potentially problematic standard library functions have been replaced with custom implementations.

### Removed Dependencies

The following external libraries have been **eliminated**:
- ❌ `<string.h>` - No longer required
- ❌ `<endian.h>` - Platform-specific, removed
- ❌ `<arpa/inet.h>` - Unix-specific, removed
- ❌ `<winsock2.h>` - Windows-specific, removed
- ❌ Platform-specific byte order headers

### Custom Baremetal Implementations

#### Memory Operations
All memory manipulation functions are implemented without `string.h`:

- **`bm_memset(void* dest, int value, size_t count)`**
  - Replaces standard `memset()`
  - Zero-initializes structures and arrays
  - Used throughout for initializing packet headers, buffers, and state

- **`bm_memcpy(void* dest, const void* src, size_t count)`**
  - Replaces standard `memcpy()`
  - Copies packet data between buffers
  - Used for payload transfers and header copying

#### String Operations
Custom string manipulation functions without `string.h`:

- **`bm_strlen(const char* str)`**
  - Replaces standard `strlen()`
  - Returns the length of a null-terminated string
  - Used for processing text-based packet traces and validation

- **`bm_strncmp(const char* s1, const char* s2, size_t n)`**
  - Replaces standard `strncmp()`
  - Compares up to `n` characters of two strings
  - Used for protocol identifier validation ("ACCL" magic bytes)
  - Returns 0 if strings match, non-zero otherwise

- **`bm_strcspn(const char* s, const char* reject)`**
  - Replaces standard `strcspn()`
  - Returns length of initial segment not containing any character from reject
  - Used for parsing hex trace files (stripping newlines)

- **`bm_strstr(const char* haystack, const char* needle)`**
  - Replaces standard `strstr()`
  - Finds first occurrence of substring
  - Used in demo program for file extension detection (.bin vs .txt)

#### Byte Order Conversion
Platform-independent byte order functions with automatic endianness detection:

- **`bm_ntohl(uint32_t)` / `bm_htonl(uint32_t)`** - 32-bit network/host conversion
- **`bm_ntohs(uint16_t)` / `bm_htons(uint16_t)`** - 16-bit network/host conversion
- **`bm_be64toh(uint64_t)` / `bm_htobe64(uint64_t)`** - 64-bit big-endian conversion

All functions automatically detect system endianness at runtime:
```c
static inline int is_little_endian(void) {
    volatile uint32_t i = 0x01234567;
    return (*((uint8_t*)(&i))) == 0x67;
}
```

For little-endian systems (x86, ARM), performs byte swapping. For big-endian systems (network byte order), returns value unchanged.

The following standard headers are still used but are **typically available in baremetal toolchains**:

- **`<stdlib.h>`** - Only for `malloc()`, `free()`, `calloc()`
  - Can be replaced with static memory pools if needed
  - See malloc removal discussion for alternatives

- **`<stdint.h>`** - Fixed-width integer types (`uint32_t`, `uint64_t`, etc.)
  - Part of C99 standard
  - Supported by all modern embedded compilers

- **`<stdbool.h>`** - Boolean type (`bool`, `true`, `false`)
  - Part of C99 standard
  - Can be manually defined if needed: `typedef int bool; #define true 1; #define false 0;`

- **`<stdio.h>`** - For `printf()`, `fprintf()`, `fopen()`, `fread()`, `fwrite()`
  - Can be replaced with custom serial output functions for output
  - File I/O can be replaced with memory-mapped I/O or custom drivers
  - Remove if no console output needed

## Comparison with ccl_offload_control.c

The reference ACCL implementation can be found in the `ACCL code` directory.

### Similarities
- **Operation handlers**: Both implement send/recv, broadcast, scatter, gather, reduce, etc.
- **Protocol support**: Both support eager and rendezvous protocols
- **Packet structure**: Header format matches ACCL specifications
- **Statistics tracking**: Both track operation counts and data volumes
- **Stream processing**: Both process packets one-at-a-time as they arrive
- **State management**: Both track operation progress and completion (NEW)
- **Collective semantics**: Handlers accurately reflect ring-based, tree-based, and flat topologies
- **Session-based tracking**: Multiple concurrent operations tracked independently

### Differences
- **Input source**: 
  - `ccl_offload_control.c` (in `ACCL code` directory): Processes live network packets from hardware
  - This implementation: Processes pre-generated trace files
  
- **Execution model**:
  - `ccl_offload_control.c` (in `ACCL code` directory): Real-time hardware offload with actual RDMA
  - This implementation: Trace-based simulation with statistics collection

- **Memory model**:
  - `ccl_offload_control.c` (in `ACCL code` directory): Fixed hardware buffers in FPGA device memory
  - This implementation: Dynamic packet allocation (malloc/free per packet)
  
- **Data operations**:
  - `ccl_offload_control.c` (in `ACCL code` directory): Performs actual data reductions (sum, max, min, etc.)
  - This implementation: Tracks data movement without actual computation

- **Rendezvous handling**:
  - `ccl_offload_control.c` (in `ACCL code` directory): Actual RDMA operations with address exchange
  - This implementation: Simulates rendezvous protocol phases

## Implementation Approach

### Handler Implementation Details

Each collective operation handler implements the specific communication pattern defined in ACCL:

#### BROADCAST Handler
```c
void accl_handle_broadcast(ACCLNodeState *node, ACCLPacket *packet) {
    // Find or create operation state by session_id
    CollectiveOpState *op = accl_find_or_create_collective_op(node, 
                                packet->header.session_id, OP_BROADCAST);
    
    // Initialize on first packet
    if (op->total_segments == 0) {
        op->total_segments = packet->header.total_segments;
        op->root_rank = packet->header.src_rank;
    }
    
    // Update progress
    op->segments_received++;
    op->bytes_processed += packet->header.data_length;
    
    // Track directional flow
    if (packet->header.src_rank == node->rank) {
        node->stats.bytes_sent += packet->header.data_length;
        // Root sending to all ranks (tree or flat topology)
    } else if (packet->header.dst_rank == node->rank) {
        node->stats.bytes_received += packet->header.data_length;
        // Non-root receiving from root
    }
    
    // Detect completion
    if (op->segments_received >= op->total_segments) {
        op->completed = true;
        printf(" [OP COMPLETE: %lu bytes total]\n", op->bytes_processed);
    }
}
```

#### ALLREDUCE Handler
```c
void accl_handle_allreduce(ACCLNodeState *node, ACCLPacket *packet) {
    // Two-phase operation: reduce-scatter + allgather
    CollectiveOpState *op = accl_find_or_create_collective_op(node, 
                                packet->header.session_id, OP_ALLREDUCE);
    
    // Initialize
    if (op->total_segments == 0) {
        // Expect packets for both phases
        op->total_segments = packet->header.total_segments * node->num_ranks * 2;
    }
    
    op->segments_received++;
    op->bytes_processed += packet->header.data_length;
    
    // Identify current phase
    const char *phase = (op->segments_received <= op->total_segments / 2) 
                        ? "REDUCE-SCATTER" : "ALLGATHER";
    
    // Ring-based bidirectional communication
    if (packet->header.src_rank == node->rank) {
        node->stats.bytes_sent += packet->header.data_length;
        printf("  [Node %u] ALLREDUCE [%s]: sending to rank %u...\n", 
               node->rank, phase, packet->header.dst_rank);
    } else if (packet->header.dst_rank == node->rank) {
        node->stats.bytes_received += packet->header.data_length;
        printf("  [Node %u] ALLREDUCE [%s]: receiving from rank %u...\n", 
               node->rank, phase, packet->header.src_rank);
    }
    
    // Completion when all phases done
    if (op->segments_received >= op->total_segments) {
        op->completed = true;
        printf(" [OP COMPLETE: all ranks have reduced result]\n");
    }
}
```

#### SEND/RECV Handler
```c
void accl_handle_send_recv(ACCLNodeState *node, ACCLPacket *packet) {
    bool is_sender = (packet->header.src_rank == node->rank);
    bool is_receiver = (packet->header.dst_rank == node->rank);
    
    if (!is_sender && !is_receiver) return; // Not relevant
    
    uint32_t peer_rank = is_sender ? packet->header.dst_rank 
                                    : packet->header.src_rank;
    
    // Find or create message state by tag and peer
    PendingMessage *msg = accl_find_or_create_pending_msg(node, 
                            packet->header.tag, peer_rank, is_sender);
    
    if (msg) {
        // Initialize on first segment
        if (msg->expected_segments == 0) {
            msg->expected_segments = packet->header.total_segments;
            msg->session_id = packet->header.session_id;
        }
        
        // Update progress
        msg->received_segments++;
        msg->bytes += packet->header.data_length;
        
        // Track directional bytes
        if (is_sender) {
            node->stats.bytes_sent += packet->header.data_length;
        } else {
            node->stats.bytes_received += packet->header.data_length;
        }
        
        // Check completion
        if (msg->received_segments >= msg->expected_segments) {
            msg->completed = true;
            printf(" [COMPLETE: %lu bytes total]\n", msg->bytes);
        }
    }
}
```

#### BARRIER Handler
```c
void accl_handle_barrier(ACCLNodeState *node, ACCLPacket *packet) {
    // Two-phase barrier: gather (entry) + scatter (exit)
    
    if (packet->header.src_rank == node->rank) {
        // Entering barrier - send notification
        node->barrier_entered++;
        printf("  [Node %u] BARRIER: entering (notification sent)\n", 
               node->rank);
    }
    
    if (packet->header.dst_rank == node->rank) {
        // Receiving notification from another rank
        node->barrier_exited++;
        printf("  [Node %u] BARRIER: received notification (%u/%u)\n", 
               node->rank, node->barrier_exited, node->num_ranks);
    }
    
    // Complete when all ranks synchronized
    if (node->barrier_entered >= 1 && 
        node->barrier_exited >= (node->num_ranks - 1)) {
        printf("  [Node %u] BARRIER: COMPLETE (synchronized)\n", node->rank);
        node->barrier_entered = 0;
        node->barrier_exited = 0;
    }
}
```

### Stream Processing (Network Simulation Mode)

This implementation uses a **streaming approach** that mirrors real network behavior:

```c
// Read file header
fread(header, ...);

// Process packets one-at-a-time
while (!feof(file)) {
    // Allocate single packet (like receiving from network)
    ACCLPacket *pkt = malloc(sizeof(ACCLPacket));
    
    // Read packet from file (like receiving from NIC)
    fread(&pkt->header, ...);
    fread(pkt->payload, ...);
    
    // Process immediately (like interrupt handler)
    accl_process_packet(node, pkt);
    
    // Free resources (like DMA buffer release)
    free(pkt->payload);
    free(pkt);
}
```

**Benefits:**
- **Memory efficient**: O(1) memory - only one packet at a time
- **Realistic**: Matches real network packet arrival behavior
- **Scalable**: Can handle unlimited trace file sizes
- **Immediate feedback**: Statistics updated in real-time per packet

## Troubleshooting

### "Cannot open file" error
- Ensure packet traces have been generated first: `python3 generate_packet_trace.py`
- Check file path is correct
- Verify file permissions

### "Invalid protocol number" error
- File is not a valid ACCL binary trace
- File may be corrupted
- Ensure you're using `.bin` file for binary format

### "Invalid hex data" error
- Hex file format is incorrect
- Use files generated by `generate_packet_trace.py`
- Check that each line has valid hex characters
