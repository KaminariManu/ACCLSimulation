# ACCL Packet Processor - Demo Application

## Overview

This directory contains the demonstration application for the ACCL Packet Processor modular library. The demo shows how to use the library to load and process packet traces generated by the PacketTraceGenerator.

## Contents

- **`demo_packet_processor.c`** - Main demonstration program
- **`demo_modular`** (or `demo_modular.exe` on Windows) - Compiled executable (created after building)

## Building the Demo

The demo is built automatically when you build the modular library.

### From the `src/` directory:

```bash
cd ../src
make
```

This will compile the modular library and link it with the demo application, creating the executable in this directory.

## Running the Demo

The demo program requires two command-line arguments:

1. **Node rank**: The rank of the node to simulate (0 to N-1, where N is the total number of nodes)
2. **Trace file**: Path to a packet trace file (binary `.bin` or hexadecimal `.txt` format)

### Examples:

```bash
# Simulate node 3 processing a binary trace
./demo_modular 3 ../../PacketTraceGenerator/output_single_node/accl_packet_trace_node3.bin

# Simulate node 0 processing a hex trace
./demo_modular 0 ../../PacketTraceGenerator/output_single_node/accl_packets_raw_hex_node0.txt

# Process an all-network trace (containing packets for all nodes)
./demo_modular 0 ../../PacketTraceGenerator/output_all_nodes/accl_packet_trace.bin
```

### Quick Test:

From the `src/` directory, you can also use:

```bash
make run
```

This will build and run the demo with a sample trace for node 3.

## What the Demo Does

The demonstration program:

1. **Initializes** a simulated node with the specified rank
2. **Loads** the packet trace from the specified file
3. **Processes** each packet through the ACCL protocol stack
4. **Displays** detailed information about each operation as it executes
5. **Prints** comprehensive statistics including:
   - Total packets processed
   - Data volume (bytes sent/received)
   - Operation breakdown (SEND/RECV, BROADCAST, REDUCE, etc.)
   - Protocol analysis (Eager vs. Rendezvous usage)
   - SoC memory usage statistics

## Expected Output

You will see detailed logs for each packet processed, showing:
- Operation type (SEND, BROADCAST, REDUCE, etc.)
- Data flow direction (sent/received)
- Segment information for multi-segment transfers
- Completion markers when operations finish
- SoC memory allocations and reductions

At the end, comprehensive statistics are displayed showing:
- Packet counts by operation type
- Protocol efficiency metrics
- Memory usage patterns
- Data volume analysis

## Using the Library in Your Own Code

This demo serves as a reference implementation. To use the ACCL packet processor library in your own application:

1. Include the main header:
   ```c
   #include "../src/include/accl_packet_processor.h"
   ```

2. Initialize a node:
   ```c
   ACCLNodeState *node = accl_init_node(rank, num_ranks);
   ```

3. Load and process packets:
   ```c
   accl_load_packets_from_binary(node, "trace.bin");
   // or
   accl_load_packets_from_hex(node, "trace.txt");
   ```

4. Print statistics:
   ```c
   accl_print_statistics(&node->stats);
   accl_print_memory_stats(&node->memory);
   ```

5. Clean up:
   ```c
   accl_free_node(node);
   ```

See `demo_packet_processor.c` for a complete working example.

## Compatibility

The demo is:
- **Cross-platform**: Works on Windows (MinGW), Linux, and macOS
- **Bare-metal compatible**: Uses only standard C99 with custom utility functions
- **Portable**: No OS-specific dependencies

## Troubleshooting

### "Cannot open file" error
- Ensure the packet trace file exists at the specified path
- Check that you've run the PacketTraceGenerator first to create trace files

### "Invalid protocol number" error
- The file is not a valid ACCL binary trace
- Ensure you're using files generated by the Python `generate_packet_trace.py` script

### "Unknown file format" error
- The demo only recognizes `.bin` (binary) and `.txt` (hex) file extensions
- Check the file extension matches the format
